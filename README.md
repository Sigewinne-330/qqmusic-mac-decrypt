# QQ 音乐解密（Mac）

把 QQ 音乐 Mac 客户端下载的加密歌曲（`.mflac` / `.mgg`）解密成普通的 `.flac` / `.ogg`。
解密算法来自开源项目 [Unlock Music](https://git.um-react.app/um/um-react)，全部在本机完成，不上传任何文件。

> 仅用于解密你自己下载的歌曲，解密后的文件请勿传播。

## 安装

需要 macOS、已登录的 QQ 音乐客户端、Node.js 22.5 或更新版本、Python 3 和 OpenSSL。建议安装 ffmpeg（提供 ffmpeg 和 ffprobe）以启用完整性校验、封面及歌词功能。

```bash
brew install node python ffmpeg
cd /你的项目路径/lib
npm ci
```

依赖从 Unlock Music 的包仓库安装。首次运行时脚本会在项目目录下创建 `密钥/` 并导出本机密钥；请勿分享或提交该目录。

## 日常用法

### 方法一：一键解密（推荐）

1. 在 QQ 音乐里正常下载歌曲。
2. 双击 **`QQ音乐解密.command`**。
3. 结果在 `~/Music/QQ音乐`：mflac → 无损 flac，mgg → ogg。窗口里每首歌都会显示 ✅ 或 ❌。

- 每次运行都会先导出最新的密钥，所以新下载的歌直接就能解。
- 已经解密过的歌会自动跳过，重复运行没关系。
- 每首歌都会做完整性校验（FLAC 比对文件自带的 MD5，ogg 做完整解码），校验不过的不会输出。
- 会自动嵌入专辑封面，见下面「关于封面」。
- 会自动抓逐字歌词，见下面「关于歌词」。
- QQ 音乐有时会把歌直接存成普通 `.flac` / `.ogg` 放在 `~/Music/QQ音乐`，这些不用解密，
  但一样会自动补封面和歌词（它们**不一定**自带内嵌封面）。
- 最后会把所有歌词同步到 LyricsBlossom，见「和 LyricsBlossom 的配合」。

### 从快捷指令启动

`快捷指令/源文件-可编辑.plist` 是快捷指令模板。先将其中的 `/你的项目路径/QQ音乐解密.command` 改成实际的绝对路径，再在终端运行：

```bash
shortcuts sign -i 快捷指令/源文件-可编辑.plist -o 快捷指令/QQ音乐解密.shortcut
```

双击生成的文件，将其添加到「快捷指令」。生成的文件不纳入仓库。

### 方法二：网页版（遇到网易云 ncm、酷狗 kgm 等其他格式时用）

1. 双击 **`打开网页版.command`**，会自动打开：浏览器里的网页版、`密钥` 文件夹、QQ 音乐下载目录（`iQmc`）。
2. 网页上方点「设置」→「QMCv2 密钥」→ 先点「清空密钥」，再点「导入数据库…」，把 `密钥` 文件夹里的 `qqmusic-mac-*.mmkv` 拖进去 → 点右下角「保存」。
3. 回到「应用」，把 `iQmc` 里的歌拖进去，逐首点「下载」，或用右下角按钮全部下载。
4. 用完关掉终端窗口，网页版就停了。

## 关于封面

封面有**两套互不相干**的机制，缺一个访达里就看不到图：

| | 存在哪 | 谁会读 |
|---|---|---|
| **内嵌封面** | 音频文件内部（FLAC 的 PICTURE 块 / OGG 的 METADATA_BLOCK_PICTURE） | 播放器（音乐 App、VLC 等） |
| **访达图标** | 文件的扩展属性（`com.apple.ResourceFork`） | 访达 |

**访达不读取 FLAC/OGG 的内嵌封面**，只看自定义图标。所以一个文件可能内嵌封面完好，
但在访达里仍是灰色音符图标；反过来也可能访达有图、文件里却没有内嵌封面。

工具两样都做：

- **解密时自动处理**：内嵌封面 + 访达图标一起写。
- **`补封面.command`**：两样都补，不区分文件来源，只看缺不缺。
  QQ 音乐直接下载的文件也**不一定**带内嵌封面（实测 36 首里有 7 首没有），所以一并处理。
  访达图标优先用文件已有的内嵌封面，没有才去下载；已经有图标的不会被覆盖。
  写入采用**原地覆盖**，文件原有的扩展属性（访达图标、QQ 音乐写的属性）都会保留；
  覆盖前先校验新内容并留备份，出问题会自动回滚。
- 封面图来自 QQ 音乐公开图床 `y.gtimg.cn`（依次尝试 800/500/300 尺寸），封面请求
  只发送专辑 mid，不带账号信息。不联网也能解密，只是没封面。
- 嵌入只改元数据，音频流原样拷贝，不会重新编码。
- 内嵌封面一律写成图片类型 **3（封面正面）**。ffmpeg 默认会写成 0（其他），
  部分播放器和音乐整理工具只认类型 3。
- 曲库数据库里查不到、文件也没有内嵌封面的歌补不了，会明确提示。
- **想去掉访达图标**：`xattr -d com.apple.ResourceFork -d com.apple.FinderInfo <文件>`。
  注意设置图标会更新文件的修改时间，但音频数据不变。

## 关于歌词

`QQ音乐解密.command` 每次都会给 `~/Music/QQ音乐` 里**所有缺歌词的歌**抓歌词
（包括 QQ 直接下载、不用解密的歌），已经有歌词的跳过，只给新歌发请求。
`补歌词.command` 只做歌词这一步，想重新抓歌词时用。
歌词放在 `~/Music/QQ音乐/歌词/`，每首两个文件，文件名和歌一致：

| 文件 | 内容 | 谁读 |
|---|---|---|
| `歌手-歌名.ttml` | 逐字原文 + 中文翻译 + 罗马音，全在一个文件里 | LyricsBlossom 等支持 TTML 的播放器 |
| `歌手-歌名.lrc` | 增强型 LRC（A2）：逐字原文 + 同时间戳的翻译行 | 绝大多数支持歌词的播放器 |

- **翻译只有逐行，没有逐字**，这是 QQ 音乐的数据本身就这样，不是抓取方式的问题。
  最终效果和 QQ 音乐客户端一致：原文逐字高亮，翻译整行跟随。
- 罗马音只有日韩语歌才有，有就存，没有就跳过。
- 纯音乐（QQ 明确标记「没有填词」）会识别出来并跳过，不会生成空文件。
- 歌曲 ID 直接取自本地曲库数据库，和你下载的文件严格一一对应，不靠歌名/歌手搜索。
- 已经有歌词的歌会跳过。歌词会通过 QQ 音乐接口联网获取。

### 和 LyricsBlossom 的配合

每次运行 `QQ音乐解密.command` 或 `补歌词.command`，工具都会把歌词写进 LyricsBlossom 自己的本地歌词库
`~/Library/Application Support/LyricsBlossom/Lyrics/`。没装 LyricsBlossom 就安静跳过。

LyricsBlossom 的本地歌词库是这样工作的（实测）：

- 每首歌是一对文件：`歌手 - 歌名 - 专辑.ttml` + `歌手 - 歌名 - 专辑.ttml.meta.json`。
- **它只在启动时**扫描这些 `meta.json` 重建索引（`lyrics_index.db`）。
  所以同步后如果 LyricsBlossom 正开着，要**重启一下它**新歌词才生效，脚本会提示。
- 播放时用播放器报给系统的「歌手 / 歌名 / 专辑」去查索引，所以 meta 里填的是
  **音频文件自己的标签**，不是 QQ 曲库里带中文括号翻译的名字。
- **歌手为空的条目不会被收录**。播放器没把歌手报给系统时（IINA 目前有这个问题，
  歌手要过一会才出现），本地歌词就用不上，它会去网上按歌名搜，Obvious 这类大众歌名容易搜错。

工具的规则：

- 你在 LyricsBlossom 里手动「指定歌词」生成的条目（`lyricsSource` 不是 `local`）**一律不动**。
- 自己生成的 meta 里带 `"generatedBy": "QQ音乐解密"`，内容没变就不重写。
- 旧版工具同步过去的 `歌手-歌名.ttml`（没有 meta，LyricsBlossom 根本不读）会被清掉，
  只删和 `歌词/` 里逐字节相同的副本。
- 音频文件没有歌手标签的歌不同步（放过去也不会被收录）。

## 第一次运行可能遇到的提示

- **「"终端"想访问其他 App 的数据」**：点「允许」。脚本需要读取 QQ 音乐的数据目录来导出密钥。
- **提示没找到 node / python3**：在终端运行 `brew install node` 或 `brew install python`。
- **没装 ffmpeg**：仍然可以解密，只是跳过完整性校验。建议 `brew install ffmpeg`。

## 出问题怎么办

| 现象 | 原因和处理 |
|---|---|
| 「密钥导出失败」 | QQ 音乐没登录过，或者客户端升级后格式变了。本工具在 QQ 音乐 **11.9.1** 上验证过，升级前建议先确认新版还能用。Unlock Music 官方推荐的稳定版本是 v8.8.0 / v10.7.1 |
| 某首歌「密钥库里找不到这首歌的密钥」 | 在 QQ 音乐里重新下载这首歌，再运行一次 |
| 某首歌「解密结果不是可识别的音频」 | 密钥和文件对不上，同样重新下载后再试 |
| 网页版报「不支持的文件类型」 | 确认导入了**最新**的密钥库并点了「保存」 |
| 某首歌「曲库里查不到，跳过歌词」 | 这首歌不在 QQ 音乐本地数据库里（比如从别处拷进来的）。歌名和歌手对得上的话可以用 LyricsBlossom 自己搜 |
| 歌词「接口返回错误码」 | QQ 那边接口变了或临时抽风，过一会再跑 `补歌词.command` |
| LyricsBlossom 里显示的歌词是别的歌 | 看它的日志 `~/Library/Application Support/LyricsBlossom/latest.log`：出现 `[LocalProvider] Found by sqlite` 才是用的本地歌词；`matching key=|歌名|` 前面是空的说明播放器没报歌手，它在网上瞎搜。个别歌不满意也可以在 LyricsBlossom 里手动指定，同步不会覆盖 |
| 新同步的歌词 LyricsBlossom 没用上 | 重启 LyricsBlossom，它只在启动时重建本地歌词索引 |

```
补歌词.command         只抓歌词 + 同步（一键解密里已经包含这一步）
打开网页版.command     启动本地网页版

lib/decrypt.mjs       批量解密脚本
lib/cover.mjs         查询专辑 mid、下载并嵌入封面
lib/add-covers.mjs    批量补封面
lib/lyrics.mjs        抓取、解密、解析歌词，输出 TTML 和 LRC
lib/add-lyrics.mjs    批量抓歌词 + 同步到 LyricsBlossom

补丁/                 对 um-react 的修改
快捷指令/             可编辑的快捷指令模板
```

## 关于补丁

官方 um-react 0.6.0 处理 QQ 音乐新版 `musicex` 格式时，如果文件内记录的媒体名不在密钥库里，
会直接用「相似文件名」模糊匹配，可能拿到别的歌的密钥，导致解密失败（例如 mgg 报「不支持的文件类型」）。
补丁改为：媒体名查不到时先按真实文件名精确查找，都查不到才模糊匹配。
详见 `补丁/um-react-musicex-fallback.patch`，基于 `补丁/um-react-base-commit.txt` 中的提交。
